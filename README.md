# discount cards

Клиентский кошелёк дисконтных карт: React 19, Vite, TypeScript, Gravity UI и Biome. Node 24, публичный npm registry (как в соседнем logscope), воспроизводимая установка через package-lock.json.

```sh
cd /Users/azakatiy/development/services/discount-cards
nvm use
npm ci
npm run dev
```

## Возможности

- Бесконечная карусель: активная карта крупнее, две соседние позади, без прозрачности. Для одной или двух карт видна только активная. Свайп, стрелки и клавиатура.
- Добавление, изменение и удаление с подтверждением; поиск, категории и избранное.
- CODE128, EAN-13 и QR генерируются на устройстве из строки; изображения кодов не хранятся. Ведущие нули сохраняются. Для EAN-13 проверяется контрольная сумма, для QR — допустимый размер UTF-8.
- Крупный экран для кассы с белой подложкой и копированием номера.
- IndexedDB, офлайн-кэш PWA, установка на главный экран, уведомление об обновлении.
- JSON-копия и опциональное шифрование AES-256-GCM с паролем. Импорт проверяет содержимое, показывает подтверждение и объединяет карты по ID, сохраняя более новую версию.
- Восстановление повреждённого хранилища из копии; защита от перезаписи изменений другой вкладки.
- Магазины: Пятёрочка (EAN-13), Магнит (QR), Лента и Лемана ПРО (Code 128). Можно выбрать магазин либо тип кода вручную.

## Проверки

```sh
npm run check
npm run typecheck
npm test
npm run build
npm run preview
```

PWA включена в production-сборке (`npm run preview`), а не в dev. Для проверки офлайна откройте preview, дождитесь готовности офлайн, перезагрузите страницу, затем отключите сеть. QR и штрихкоды проверяются настоящим кодировщиком в тестах, но считывание конкретным кассовым сканером требует проверки на устройстве.

## Сборка PWA

Манифест и service worker **генерируются при `npm run build`**, вручную добавлять или менять файлы в `dist/` не нужно. Единственный источник PWA-настроек — `pwa.config.ts`: содержимое манифеста, относительные `start_url`/`scope`, набор кэшируемых файлов и политика обновления. `vite.config.ts` подключает эту конфигурацию к `vite-plugin-pwa`.

Используется `generateSW`: Workbox создаёт `dist/sw.js` и свой runtime, Vite PWA создаёт читаемый `dist/manifest.webmanifest` и добавляет его в HTML. Регистрация остаётся через `virtual:pwa-register/react`; обновление активируется после подтверждения пользователя. Иконки копируются из `public/`. Эти файлы не нужно хранить как отдельные исходники. Если появится собственная логика service worker (например, background sync), можно перейти на `injectManifest` и исходный `src/sw.ts`; сейчас такого требования нет.

После успешной сборки `.reports/pwa-build.json` содержит манифест и список precache-ресурсов с ревизиями и размерами. Отчёт создаётся build-only модулем `pwa-report.ts` через публичные hooks Vite PWA/Workbox, без разбора или изменения минифицированного JS. Проверки сборки отклоняют отсутствующие обязательные ресурсы и абсолютные/внешние пути. Отчёт учитывает также дополнительные записи иконок и манифеста, которые плагин передаёт Workbox отдельно от glob-файлов. Он находится вне `dist/`, не публикуется и относится только к последней успешной сборке; после неудачной сборки его нельзя считать подтверждением готовности приложения.

Тесты проверяют разрешение URL в корне и подпапке, наличие объявленных иконок и подтверждение обновления. Для ревью меняйте `pwa.config.ts` и смотрите JSON-отчёт, а не сгенерированный `sw.js`. В dev на 5173 service worker по-прежнему отключён; его поведение проверяется через production preview.

## Размещение

Для GitHub Pages подготовлен workflow `.github/workflows/pages.yml`: проверки pull request и публикация успешной сборки из `main`. Однократная настройка репозитория и проверка PWA описаны в [docs/github-pages.md](docs/github-pages.md).

`npm run build` создаёт полностью статическую папку `dist/`. Разместите её на любом HTTPS-хостинге. Сервер приложения, база на сервере, переменные окружения и секретные ключи не нужны. `base: './'` поддерживает размещение в подпапке (открывать URL с завершающим `/`). Раздавайте `sw.js` и `index.html` без длительного кэширования, хэшированные `/assets/*` можно кэшировать надолго. Manifest должен иметь корректный MIME `application/manifest+json`.

Используются локально поставляемые шрифты: нет обращений к Google Fonts, аналитики или внешних API. В production кэшируются HTML, скрипты, стили, шрифты и иконки. Для установки PWA требуется HTTPS (исключение — localhost).

Данные привязаны к origin браузера: другой домен, порт, браузер или устройство означает отдельный кошелёк. Это не облачная синхронизация. При очистке данных сайта карты исчезнут; сохраняйте резервную копию. Пароль защищает экспортированный файл, но не саму IndexedDB.

Подробнее о вариантах хранения и будущей синхронизации: [docs/storage.md](docs/storage.md).

## Структура

`src/App.tsx` — маршруты; `src/pages/` — страницы; `src/layouts/` — общая оболочка; `src/context/` и `src/hooks/` — состояние и PWA; `src/components/` — карусель, коды и формы; `src/lib/` — данные, магазины, шифрование и тесты; `src/i18n/` — локализация; `vite.config.ts` — Vite; `pwa.config.ts` — манифест и правила service worker.

Готовые иконки лежат в `public/`. Скрипт генерации и зависимость `sharp` удалены. В `dist/` входят только ресурсы приложения; исходники, тесты, README и вспомогательные инструменты не публикуются.

## Известные ограничения зависимостей

На момент проверки npm audit сообщает 6 замечаний (2 low, 4 moderate) в dev-цепочке сборки service worker: workbox-build → glob/minimatch и @rollup/plugin-node-resolve → deepmerge. Автоматически предложенный fix — смена major-версии vite-plugin-pwa; он не применялся. Эти пакеты не используются браузером как исполняемый runtime.

## Маршруты и локализация

React Router использует hash-маршруты: `#/` — кошелёк, `#/settings` — хранение, `#/cards/new` — добавление, `#/cards/:id` — показ кода, `#/cards/:id/edit` — редактирование, `#/cards/:id/delete` — подтверждение удаления. Навигация поддерживает Back/Forward. При прямом открытии диалога сначала загружаются карты. Неизвестный путь или отсутствующая карта показывает понятное состояние. Hash не отправляется серверу, поэтому маршруты работают на статическом хостинге и в подпапке без серверных rewrites. Офлайн доступен после первого успешного кэширования production-сборки.

`createAppI18n(locale)` создаёт синхронно готовый экземпляр i18next; `appI18n` — общий экземпляр приложения. Сейчас поддерживается `ru`, `ru-RU` нормализуется до `ru`; неизвестные локали используют русский fallback. React получает экземпляр через `I18nextProvider`. Все тексты находятся в едином плоском объекте `translations` в `src/i18n/translations.ts`, без сети. Ключи содержат только маленькие латинские буквы, цифры, точки и дефисы (например, `pages.wallet.add-favorite`). Точки — часть ключа (`keySeparator: false`), разделитель плюрализации — дефис (`pluralSeparator: "-"`). Плюральные ключи используют JSON v4 (`-one`, `-few`, `-many`, `-other`) и правила Intl/CLDR; вызов `t('common.cards', {count: 21})` возвращает «21 карта». Для форматирования доступны стандартные Intl formatter-функции i18next. Интерполяцию экранирует React, HTML из переводов не вставляется.

Данные карты отделены от интерфейсных переводов: пользовательские названия, заметки и произвольные категории не переводятся. Старые русские категории отображаются через таблицу ключей без изменения сохранённых данных. Необязательный `storeId` сохраняется в IndexedDB и резервной копии; старые карты без него открываются в ручном режиме.

## Gravity UI и стили

Типографика интерфейса использует `Text` из Gravity UI: `as` сохраняет семантику заголовков, абзацев, подписей полей и легенд, а `variant` задаёт роль текста. Декоративные элементы остаются обычными элементами; Gravity Button управляет своим текстом сам. В навигации и других интерактивных элементах с собственной адаптивной метрикой используется `variant="inherit"`.

`src/theme.css` настраивает публичные переменные Gravity: палитру, состояния контролов, границы, радиусы и типографическую шкалу. `ThemeProvider` добавляет `discount-cards-theme` к корню Gravity на `body`, поэтому тема применяется также к диалогам и порталам. Переменные темы переопределяются на `.g-root.discount-cards-theme`, а не только на `:root`, где их перекрыли бы значения библиотеки.

Стили компонентов, страниц и оболочки находятся в соседних `*.module.css`; общие небольшие визуальные паттерны — в `src/styles/shared.module.css`. Глобальный `src/styles.css` содержит только reset, базовые правила документа, focus и reduced-motion. Состояния карусели остаются локальными классами, позиции и пользовательские цвета — CSS custom properties. У Barcode есть явные режимы размера и отображения номера, поэтому страницы не зависят от его внутренних CSS-классов.
